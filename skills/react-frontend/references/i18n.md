# Internationalization (i18n)

Default library: **react-i18next** (unless the project already uses another one).

## Setup

Setup and locale files live in `shared/i18n/` (business-agnostic infrastructure). Init
runs once in `src/app/` before rendering — not in a component effect
(`hooks-and-rendering.md`, "App-wide initialization runs once").

```ts
// shared/i18n/i18n.ts
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import en from './locales/en.json'

// Other locales load on demand — statically analyzable imports (performance.md)
const LOCALES = {
  de: () => import('./locales/de.json'),
} as const

export async function initI18n(language: string): Promise<void> {
  await i18n.use(initReactI18next).init({
    resources: { en: { translation: en } },
    lng: 'en',
    fallbackLng: 'en',
    interpolation: { escapeValue: false }, // React already escapes
  })
  await changeLanguage(language)
}

export async function changeLanguage(language: string): Promise<void> {
  const load = LOCALES[language as keyof typeof LOCALES]
  if (load && !i18n.hasResourceBundle(language, 'translation')) {
    i18n.addResourceBundle(language, 'translation', (await load()).default)
  }
  await i18n.changeLanguage(language)
  document.documentElement.lang = language // keep <html lang> in sync [WCAG 3.1.1]
}
```

## Rules

- **No hard-coded UI strings** — every visible text, `aria-label` and `alt` comes from
  the translation files.
- Keys in lower case with dot notation, with context in the key
  (`greeting.welcome`, not `welcome`; `user.profile.title`).
- **All keys maintained**: none missing, none dead — check with a key extractor
  (e.g. `i18next-parser`) in CI.
- Plurals through `count` (`t('cart.items', { count })`), never by string concatenation;
  numbers, dates and currencies through `Intl` / i18next formatting, not by hand.
- `escapeValue: false` is correct only because React escapes text — never pass a
  translation into `dangerouslySetInnerHTML` (`security.md`).
- The language switcher is a real form control with a label; the current language is
  persisted as a non-sensitive preference (`data-and-state.md`, persisted state).
- `<html lang>` follows the UI language; text in another language gets its own `lang`
  attribute (`accessibility.md`).
